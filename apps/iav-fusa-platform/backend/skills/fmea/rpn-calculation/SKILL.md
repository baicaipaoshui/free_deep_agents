# Stage 3 — `calculate_rpn`（可能触发审批门）

## 职责

对 Stage 2 输出的每条失效模式，依据标准评分体系精确评估 S/O/D，计算 RPN = S × O × D。
识别超过阈值的高风险条目，触发 `rpn_review` 审批门。

- 填充 `FMEAState.rpn_scores`
- 更新 `FailureModeEntry` 的 `severity/occurrence/detectability/rpn` 字段（精确值）
- 将超阈值条目 ID 加入 `FMEAResult.high_rpn_modes`

## RPN 阈值说明

**`RPN_THRESHOLD`** 由环境变量配置（默认值 **100**）。
- `rpn > RPN_THRESHOLD` → 加入 `high_rpn_modes`，触发 `awaiting_approval=True`，`approval_type="rpn_review"`
- `rpn ≤ RPN_THRESHOLD` → 记录为可接受风险，文档存档

⚠️ **审批门触发后：** 高 RPN 条目列表通过 WebSocket 推送到前端。工程师在审批界面确认（或驳回要求重新评估）后，Pipeline 继续执行 Stage 4。

## S — 严酷度（Severity，1-10）

评估失效模式**对系统最终用户的影响**（与 HARA S 不同，这里是 1-10 FMEA 尺度）：

| 分值 | 影响等级 | 典型描述 |
|------|---------|---------|
| **10** | 危险（无预警）| 可能伤害人员且无预警信号，违反安全法规 |
| **9** | 危险（有预警）| 可能伤害人员，有预警信号 |
| **8** | 极高 | 功能完全丧失，整车无法运行 |
| **7** | 高 | 功能严重退化，整车勉强可运行 |
| **6** | 中高 | 功能退化，次级功能丧失，驾驶员不适 |
| **5** | 中 | 功能降低，用户强烈不满 |
| **4** | 低中 | 功能轻微降低，用户不满 |
| **3** | 低 | 功能基本正常，轻微缺陷，部分用户察觉 |
| **2** | 极低 | 轻微不适，大多数用户察觉不到 |
| **1** | 无影响 | 用户察觉不到任何变化 |

**与 HARA ASIL 的对应关系（参考）：** S3→FMEA S 8-10；S2→S 5-8；S1→S 2-5；S0→S 1-2

## O — 发生频次（Occurrence，1-10）

评估**该失效模式**在产品寿命期内的发生概率：

| 分值 | 频率描述 | 失效概率（每百万次操作/小时）|
|------|---------|------------------------|
| **10** | 极高 | ≥ 100 次/million |
| **9** | 极高 | 50~100 次/million |
| **8** | 高 | 20~50 次/million |
| **7** | 高 | 10~20 次/million |
| **6** | 中高 | 2~10 次/million |
| **5** | 中 | 0.5~2 次/million |
| **4** | 中低 | 0.1~0.5 次/million |
| **3** | 低 | 0.01~0.1 次/million |
| **2** | 极低 | 0.001~0.01 次/million |
| **1** | 极低 | < 0.001 次/million |

**参考依据：** 历史数据 / ISO 26262 Part 5 Annex B 硬件失效率 / 供应商规格书 / AIAG 历史 O 值表

## D — 检测性（Detectability，1-10，分越高越难检测）

评估**现有控制措施**发现该失效模式（在其影响到用户之前）的能力：

| 分值 | 检测能力 | 描述 |
|------|---------|------|
| **10** | 无 | 无检测手段，失效直接到达用户 |
| **9** | 极低 | 人工目检，高度依赖检验人员技能 |
| **8** | 低 | 随机抽样检测，大量漏检 |
| **7** | 低中 | 功能测试（部分覆盖），仍有漏检 |
| **6** | 中 | 系统自诊断（在线），有漏检窗口 |
| **5** | 中高 | 系统自诊断 + 周期性诊断，漏检率低 |
| **4** | 高 | 全覆盖系统测试，有监控警告 |
| **3** | 高 | 统计过程控制（SPC），大部分情况可检测 |
| **2** | 极高 | 100% 自动检测（防错/Poka-yoke），几乎不会漏检 |
| **1** | 绝对 | 防错机制完善，不可能到达用户 |

## RPN 计算与分类

```
rpn = severity × occurrence × detectability
```

| RPN 范围 | 风险等级 | 处理策略 |
|---------|---------|---------|
| > `RPN_THRESHOLD`（默认100）| 高风险 | 加入 `high_rpn_modes`，**触发审批门** |
| 50~`RPN_THRESHOLD` | 中风险 | 工程判断，建议改进，记录理由 |
| < 50 | 低风险 | 可接受，文档存档 |

**注意：** 即使 RPN 较低，若 S = 9 或 10，也**必须**单独标注并强制要求提出措施（安全豁免原则）。
