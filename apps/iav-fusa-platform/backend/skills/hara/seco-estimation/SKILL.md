# Stage 4 — `estimate_seco`（触发审批门）

## 职责

对 Stage 3 输出的每个危险事件，精确评估 S/E/C 三参数。
结果填充到 `HARAState.seco_ratings`，格式严格对应 `SECORating` schema。

⚠️ **此阶段完成后自动触发 `asil_confirmation` 审批门：**
- `awaiting_approval = True`
- `approval_type = "asil_confirmation"`
- 评估结果通过 WebSocket 发送到前端供工程师确认
- 人工确认后 Pipeline 才继续执行 Stage 5（ASIL 定级）

## S — 严酷度（Severity）评分标准

评估**最坏合理情况**下的人员伤害程度（整数 0-3）：

| 等级 | 定义 | 典型示例 |
|------|------|---------|
| **S0** | 无伤害（仅财产损失或无影响） | 信息娱乐系统故障 |
| **S1** | 轻伤（可治愈，无永久伤残） | 低速轻微追尾，软组织损伤 |
| **S2** | 重伤（永久伤残或生命受威胁，存活概率高） | 中速碰撞，骨折/内伤 |
| **S3** | 致命（存活概率低或死亡） | 高速失控正面碰撞 |

**重要：** 考虑车内乘员、行人、其他道路参与者。S 取所有受影响人员中的最大值。

## E — 暴露概率（Exposure）评分标准

评估车辆处于该**工况**的时间比例（整数 0-4）：

| 等级 | 时间比例 | 典型工况 |
|------|---------|---------|
| **E0** | <0.001% | 赛道、特殊试验场景 |
| **E1** | 0.001%~0.01% | 极低频特殊驾驶场景 |
| **E2** | 0.01%~0.1% | 紧急制动、湿滑路面 |
| **E3** | 0.1%~10% | 高速行驶、弯道行驶 |
| **E4** | >10% | 城市行驶、停车操作 |

**注意：** E 评估工况的时间比例，而非失效本身的概率。

## C — 可控性（Controllability）评分标准

评估**普通驾驶员**在该危险事件发生后，能否在合理时间内将车辆带到安全状态（整数 0-3）：

| 等级 | 比例 | 定义 |
|------|------|------|
| **C0** | >99% | 通常可控，几乎所有驾驶员能处置 |
| **C1** | >90% | 简单可控，经过训练的驾驶员能处置 |
| **C2** | ~90% | 普通可控，约 90% 的驾驶员能处置 |
| **C3** | <90% | 难以控制，<90% 能处置或完全不可控 |

**评估依据：**
- 危害发生到需要响应的时间窗口
- 驾驶员能否感知到危害（预警信号）
- 是否需要特殊驾驶技能才能处置

## 评估思路示例（EPS 转向辅助失效 × 高速行驶）

- **S = 3**：高速行驶（>100km/h）时转向失去辅助，驾驶员可能无法保持车道，导致致命碰撞
- **E = 3**：高速行驶占总驾驶时间约 5%~15%（E3）
- **C = 3**：高速行驶时方向盘突然变重，驾驶员几乎无法及时补偿，大多数驾驶员会失控（C3）
- **ASIL 查表 → ASIL-C**（通过 `asil_lookup` 工具验证）

## 每条记录格式（对应 `SECORating` schema）

```json
{
  "scenario": "高速行驶（>100km/h）时转向辅助完全失效",
  "severity": 3,
  "exposure": 3,
  "controllability": 3,
  "asil": "ASIL-C",
  "rationale": "S3：高速失控可致死亡；E3：高速行驶占驾驶时间约5%；C3：转向突然变重，普通驾驶员无法及时补偿"
}
```

**注意：** `asil` 字段值由 Stage 5 的 `asil_lookup` 工具最终确认，此处为预估，需与工具结果保持一致。

## 审批门触发说明

此阶段结束后系统自动暂停，前端弹出审批界面显示本表。
工程师确认或修改 S/E/C 评分后，点击"批准"，Pipeline 继续执行 Stage 5。
若工程师修改了评分，需重新调用 `asil_lookup` 重新定级。
